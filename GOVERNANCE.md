# Governance

Vertical Route Language starts with Pedro Guzmán as initial author and maintainer. The project is intended to grow into an international, community-maintained open source project.

## Decision Making

The project uses lazy consensus for routine changes. A proposal can move forward when maintainers have had a reasonable chance to review and no blocking objections remain.

Architecture, syntax, safety-related semantics, package naming, and governance changes require explicit maintainer review. These decisions should be documented in issues, pull requests, or Architecture Decision Records when the impact is significant.

## Project Values

VRL prioritizes readable route documents, portable structured data, careful rendering, domain accuracy, accessibility, and strict architecture boundaries.

## Maintainer Changes

Maintainers can be added through nomination by an existing maintainer and consensus among current maintainers. Maintainers can step down voluntarily. Removal for inactivity or Code of Conduct violations should be handled privately when possible and documented clearly when project access changes.
